# Remote presentation development

Stage 4 is in progress. Capable imported sessions open an independent presentation stream. Provisioned WSL origins advertise v1 only after the Windows endpoint confirms readiness. Presenter grants, the question subset and origin-run program jobs are enabled. Pages remain unimplemented and unadvertised.

Discovery retains a positive integer `remote.presentation`; absent, null, invalid or nonpositive optional values leave a usable terminal inventory with presentation unavailable. A higher positive version is a maximum-version advertisement; protocol v1 is the only implemented wire version. Persisted old bindings remain terminal-only. The pane UUID comes from the verified daemon name, matching upstream `ZmxSupport.paneIdentity` and `RemoteBinding`, never its left/right role. Presentation target keys include WSL distribution/user, SSH destination, origin control socket, endpoint, session and stable pane. Keys do not replace existing daemon-incarnation verification.

The envelope decoder bounds UTF-8 JSON lines to 256 KiB, rejects duplicate fields recursively, and preserves generation/revision on unknown additive kinds without exposing their payload for execution. Incremental framing has fixed memory usage and fails on partial EOF. Negotiation intersects explicitly implemented capabilities; decoding an envelope alone does not authorize its payload. Family-specific validation and UI handlers remain separate work.

## Internal stream endpoint

The provisioned Rust adapter accepts exactly `zmx present SESSION` and performs fresh scoped discovery before starting the bundled `agwintermctl zmx export present`. The CLI requires exact window/session UUIDs plus distribution, Linux user, application origin, ZMX executable/socket directory, adapter and selected control pipe. Its first pipe line is `zmx.export.present` with those selectors, followed by bounded v1 frames on the same reader. The server verifies the Windows SID, exact open window, fresh eligible session and immutable daemon identity. No generic control JSON is accepted after the stream opens. This endpoint is internal; it does not grant arbitrary CLI forwarding.

The broker atomically orders hello/snapshot before live deltas, filters snapshot families to negotiated kinds, caps subscribers at 16 per origin and disconnects a subscriber whose 256-frame queue fills. The CLI/native relays enforce 256 KiB lines, partial-EOF refusal, write/idle deadlines, concurrent bounded stderr draining and endpoint revocation. All process cleanup is limited to the presentation child, independent of terminal attachment processes.

## Passive compatibility and degradation

Status uses native severity, blink and timestamp; status color/shape overrides are explicitly refused by this initial handler. Context remains transient on the replica and is not saved over local context. HUD uses native text/Markdown, spinner, colors, nine positions, size, font, sticky/frame and mapped-pane rendering with the origin's remaining lifetime. Unknown panes, scratch anchors, unsupported options and occupied local overlay slots fail the presentation stream without changing terminal geometry. A new connection replaces passive state and never replays notifications.

Negotiated sound is a live event sent only to the current presenter, separately from terminal leadership. A null name uses the viewer's blocked-sound preference; explicit `default`/`beep` names are portable. Windows-specific files/aliases stay on the Windows origin. On Windows viewers, known system sounds play directly and unknown remote names fall back to the system alert, matching agterm's fallback policy. Remote paths never authorize reading viewer-local files. Only the viewer's own preference may name a local WAV file. An explicit sound on a blocked transition replaces its automatic blocked sound. Notification banners use each viewer's notification-sound preference. Mirrored notifications/sounds never feed the origin publication path; OSC notifications already travel with terminal output and are not republished. Neither event family is stored in snapshots or replayed after outage. Queue acceptance is not a delivery acknowledgement; lost sounds/notifications are not retried.

Presentation failures clear mirrored state, expose `presentationError`/`presentationConnected` in remote pane readback and retry with bounded consecutive backoff. Legacy bindings without a capability remain terminal-only. Questions now accept optional `ask open --target EXACT_SESSION_UUID`; omission retains window-only ownership. Result/cancel IDs are always question IDs. Session-targeted questions retain both owners and cancel with `owner-closed` when their exact session disappears, including workspace disposal and soft-close; they never follow the active session.

## Origin-run program jobs (2026-11-03)

The origin reserves a session or stable-pane slot for 15 seconds and generates a single-claim ID. The presentation frame contains the job ID, pane and rendering metadata only. Command, cwd and configured profile environment stay at the origin. At most 256 origin records are retained; launch context is capped at 128 KiB. Claims check the Windows SID, exact exported endpoint/window/session and current presenter under the broker lock. Expiry, rejection and pre-claim presenter loss cannot execute a program. Ordinary HUD, web and local program opens respect a reserved slot.

The explicitly provisioned Rust adapter additionally accepts exactly `session overlay run-job JOB`. It verifies its private Linux-account endpoint and current tree, then opens the bundled CLI's internal `zmx export job` channel with the exact scope. This is not a generic command relay. The Linux helper receives the origin context, runs `/bin/sh -lc` under the inherited SSH PTY with a separate foreground process group, forwards terminal input/resize through that PTY and reports exit to the Windows origin. Cancellation/hangup terminates that job group with a bounded TERM/KILL grace. A nonblocking control writer keeps an unavailable Windows relay from blocking PTY supervision. No base ZMX workload is created or owned by this channel, and no new runtime is installed.

Windows viewers launch only the scoped `agtermctl session overlay run-job` SSH command through the Rust PTY host. They do not receive the executable program text or reinterpret its cwd. Stable pane mapping survives role changes; hidden/unknown panes and occupied slots refuse. Session percent sizing, pane full-size, background color, follow and wait are supported. `overlay.points` remains unadvertised; width/height and origin-side delegated hide/show/toggle/text/copy refuse explicitly. Origin `--block` returns its own job outcome; held `--wait` surfaces keep the slot until closed. Existing local overlay behavior and window-wide result behavior remain unchanged.

Presentation-only loss retires unclaimed reservations and closes ended held replicas, but leaves a claimed program on its independent PTY. The orphan closes when that channel exits; reconnect neither adopts it nor retries its command. Origin close, owner removal and job-channel loss settle one retained outcome. A late exit cannot overwrite a prior cancellation. No terminal leadership is obtained by an overlay.
