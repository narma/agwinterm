# Remote presentation development

Stage 4 is in progress. Capable imported sessions open an independent presentation stream. Provisioned WSL origins advertise v1 only after the Windows endpoint confirms readiness. Presenter grants and the question subset are enabled; program jobs and pages remain unimplemented and unadvertised (basic unflagged overlay requests are explicitly rejected).

Discovery retains a positive integer `remote.presentation`; absent, null, invalid or nonpositive optional values leave a usable terminal inventory with presentation unavailable. A higher positive version is a maximum-version advertisement; protocol v1 is the only implemented wire version. Persisted old bindings remain terminal-only. The pane UUID comes from the verified daemon name, matching upstream `ZmxSupport.paneIdentity` and `RemoteBinding`, never its left/right role. Presentation target keys include WSL distribution/user, SSH destination, origin control socket, endpoint, session and stable pane. Keys do not replace existing daemon-incarnation verification.

The envelope decoder bounds UTF-8 JSON lines to 256 KiB, rejects duplicate fields recursively, and preserves generation/revision on unknown additive kinds without exposing their payload for execution. Incremental framing has fixed memory usage and fails on partial EOF. Negotiation intersects explicitly implemented capabilities; decoding an envelope alone does not authorize its payload. Family-specific validation and UI handlers remain separate work.

## Internal stream endpoint

The provisioned Rust adapter accepts exactly `zmx present SESSION` and performs fresh scoped discovery before starting the bundled `agwintermctl zmx export present`. The CLI requires exact window/session UUIDs plus distribution, Linux user, application origin, ZMX executable/socket directory, adapter and selected control pipe. Its first pipe line is `zmx.export.present` with those selectors, followed by bounded v1 frames on the same reader. The server verifies the Windows SID, exact open window, fresh eligible session and immutable daemon identity. No generic control JSON is accepted after the stream opens. This endpoint is internal; it does not grant arbitrary CLI forwarding.

The broker atomically orders hello/snapshot before live deltas, filters snapshot families to negotiated kinds, caps subscribers at 16 per origin and disconnects a subscriber whose 256-frame queue fills. The CLI/native relays enforce 256 KiB lines, partial-EOF refusal, write/idle deadlines, concurrent bounded stderr draining and endpoint revocation. All process cleanup is limited to the presentation child, independent of terminal attachment processes.

## Passive compatibility and degradation

Status uses native severity, blink and timestamp; status color/shape overrides are explicitly refused by this initial handler. Context remains transient on the replica and is not saved over local context. HUD uses native text/Markdown, spinner, colors, nine positions, size, font, sticky/frame and mapped-pane rendering with the origin's remaining lifetime. Unknown panes, scratch anchors, unsupported options and occupied local overlay slots fail the presentation stream without changing terminal geometry. A new connection replaces passive state and never replays notifications. Sound delegation remains unavailable until presenter arbitration is implemented.

Presentation failures clear mirrored state, expose `presentationError`/`presentationConnected` in remote pane readback and retry with bounded consecutive backoff. Legacy bindings without a capability remain terminal-only. Questions now accept optional `ask open --target EXACT_SESSION_UUID`; omission retains window-only ownership. Result/cancel IDs are always question IDs. Session-targeted questions retain both owners and cancel with `owner-closed` when their exact session disappears, including workspace disposal and soft-close; they never follow the active session.

Presenter grants are independent of terminal leadership and use first-acquire-wins, idempotent reacquisition, subscriber-loss revocation and distinct owner generations. Terminal transport replacement with the same verified workload/pane identities retains presentation authority. Origin responses check exact scope, subscriber, owner and question ID before first-completion settlement.

Question conversion supports buttons, one line/multiline input, single/multi-choice and negotiated Other; it retains typed field IDs at the origin, default/cancel buttons, prefilled text and checked IDs. Accepted delegated radio semantics select the first item initially and make Other exclusive; local forms retain previous semantics. Native UI limits apply: at most six buttons and fifty choices, native text limits; multi-field forms, choice subtitles, explicit width and destructive styling refuse instead of truncating. Terminal/GUI styles use the native form on Windows; native multiline CRLF is encoded as protocol LF. Unsupported native forms remain local with a diagnostic. Answer delivery is never retried; the viewer reads the exact origin result over a bounded read-only command or exposes an uncertain outcome. Stream loss dismisses the replica and returns a still-pending origin question under its original ID.
