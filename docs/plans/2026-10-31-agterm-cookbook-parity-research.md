# План исследования паритета с agterm и cookbook

Дата: 2026-10-31. Статус: первичный обзор выполнен, подробный аудит и реализация не начаты.

Цель — определить, какие полезные сценарии agterm доступны в Agwinterm, какие требуют
адаптации рецептов, а какие упираются в недостающие возможности терминала. В дальнейший
roadmap также входят исследование просмотра веб-контента внутри приложения и OSC 8.
Результатом
исследования должен стать приоритизированный список работ с доказательствами и критериями
готовности. Совпадение названий команд само по себе не означает паритета сценария.

Текущий запрос разрешает исследование и фиксацию плана. Реализация, установка рецептов,
изменение пользовательских hooks/keymap/config, запуск сторонних скриптов и выпуск релиза
в этот план не входят. Предыдущее разрешение на C0–C8 не распространяется на новые работы.

- [Трекер паритета](../agterm-parity.md) связывает октябрьский план с более ранними

В этом исследовании исторические документы не переписываются.

## Первичные выводы

1. **Многие сценарии стоит сначала проверять как внешние рецепты.** Native picker,
   ask/forms, program overlays, HUD, events/wait, рабочие наборы, история закрытого
   и управление окнами уже дают значительную основу. Нужна проверка конкретных
   аргументов, ответов и жизненного цикла, прежде чем добавлять новые команды.
2. **Claude/Codex resume уже имеет собственный механизм.**
   [SessionStart и session.bind](../control-api.md#sessionbind-from-a-sessionstart-hook)
   сохраняют разговор и параметры запуска, включая [WSL](../wsl.md).
   Сначала сравнить результат восстановления конкретной панели с upstream-рецептами;
   не устанавливать параллельные shell wrappers без выявленного пробела.
3. **Наличие API не делает shell-скрипт переносимым.** Проверять JSON-конверты и exit
   codes, `AGT_*`/`AGTERM_*` против `AGWINTERM_*`, окно и экземпляр приложения,
   точные pane IDs, Windows/WSL cwd и quoting. В `native-dir-picker` список корней
   делится по `:`, что нельзя переносить на Windows drive paths. `project-launcher`
   использует zsh и временный файл prompt, а наш
   [session new](../session-commands.md) имеет собственные режимы запуска.
4. **Хранение истории не равно возобновлению разговора.**
   [recent open](../recent-work.md) восстанавливает оболочки и настройки, но не
   воспроизводит agent bindings или captured programs. `park-and-resume` и
   `session-snapshot` требуют отдельной проверки долговечности снимков и replay.
5. **Есть сценарии за прежними архитектурными границами.** HTML/JS/page bridge
   (`html-doc-overlay`, `annotate-document`) и zmx (`remote-session-picker`) не покрыты
   прежним планом. Внешний браузер или обычный SSH могут быть альтернативным сценарием,
   но не должны считаться полным эквивалентом embedded HTML или zmx attach.
   Просмотр веб-контента включён в новое исследование по уточнению пользователя;
   исключение HTML из C0–C8 не является отказом от этого направления в новом roadmap.
6. **Windows foreground hints не доказывают готовность prompt.** Это существенно
   для `same-dir`, reset, automation между агентами и классификации busy/idle;
   см. [контракт hints](../navigation.md#foreground-shell-hints).
7. **Новая волна upstream шире v0.38.1.** Например,
   [named-companion](https://github.com/umputun/agterm/blob/714ec616c81add35627a1f8c3d5cb50ab9e030a1/cookbook/named-companion/README.md)
   требует companions и row tints из 0.39.0. Обычный `session duplicate` не доказывает
   наличие связей parent/companion, replay программ и такого оформления.

## Дальнейший roadmap за пределами C0–C8

Уточнение пользователя от 31 октября: добавить ранее обсуждавшиеся просмотр
веб-контента внутри приложения и поддержку OSC 8. Исходный отдельный чат с полным
дальнейшим roadmap пока не найден. Два направления ниже подтверждены текущим запросом;
прочие пункты того обсуждения нужно восстановить по источнику, не угадывать.

### Просмотр веб-контента внутри приложения

Пользовательский результат — открыть и просмотреть веб-контент, связанный с текущей
работой: страницу, локальный HTML-отчёт или документ. Речь о способе просмотра содержимого,
а не только об открытии ссылки во внешнем браузере. Выбор renderer и объём browser API
пока не приняты.

- [ ] Восстановить исходное обсуждение и перенести остальные решения и пункты roadmap.
- [ ] Уточнить нужный уровень содержимого: локальные HTML-документы, страницы по URL,
  локальные web dashboards; отдельно определить необходимость JavaScript, форм и навигации.
- [ ] Сравнить варианты встроенного просмотра: отдельная web-панель/overlay с browser
  engine, ограниченный HTML renderer и текстовый просмотр. Оценить качество страниц,
  совместимость с нативным UI, зависимости поставки, память и жизненный цикл.
  Внешний браузер рассматривать как fallback, явно отличая от встроенного просмотра.
- [ ] Пересмотреть исходную границу no-web для отдельной поверхности просмотра.
  Зафиксировать, какие части архитектуры меняются и как это соотносится с нативным
  рендерингом терминальной сетки. Старый запрет не закрывает исследование заранее.
- [ ] Описать владение окном/сессией, focus/input, hide/show/close, DPI, theme,
  доступность, ссылки, download и локальные Windows/WSL paths.
- [ ] Отдельно оценить изоляцию web-содержимого, хранение browser state и доступ
  страницы к terminal/control API. Просмотр страницы не должен автоматически означать
  наличие privileged JS bridge; такой контракт требует отдельного решения.
- [ ] Сопоставить выбранный вариант с `html-doc-overlay`, `annotate-document`,
  web-частью `scheduled-jobs` и `session-snapshot`. Для каждого указать, достаточно ли
  только просмотра или нужны интерактивность, submit/result и обратная связь с агентом.

Готовность исследования: сравнение вариантов, рекомендуемый первый объём, список
архитектурных изменений, зависимостей и критериев приёмки. Полный встроенный браузер
и паритет JS bridge не считаются согласованными лишь из-за запроса на просмотр.

### OSC 8 и ссылки в терминале

Пользовательский результат — терминальные приложения передают явный URI вместе с
видимым текстом ссылки, Agwinterm сохраняет эту связь и позволяет открыть адрес.
Это самостоятельная terminal capability; ей не требуется встроенный web renderer.

- [ ] Проверить текущее состояние managed и Rust engines, модель cell attributes,
  scrollback/reflow, рендерер, mouse hit testing и путь открытия URI.
  [Июльский gap analysis](../agterm-gap-analysis-2026-07.md) фиксировал отсутствие
  OSC 8 и URL detection, но не служит доказательством состояния текущей сборки.
- [ ] Спланировать обработку открытия/закрытия OSC 8, параметра ID и URI;
  ограничение размеров и время жизни link metadata, включая main/alternate screens.
- [ ] Определить сохранение ссылок при прокрутке, переносах, resize, overwrite,
  selection/copy и при включённом сохранении буфера. Сверить managed/Rust поведение.
- [ ] Выбрать hover/подсказку адреса, жест открытия и допустимые URI schemes;
  определить открытие во внешнем браузере и, при наличии, во встроенной поверхности.
- [ ] Проверить доставку OSC 8 через Windows/ConPTY и WSL отдельно. Автоматическое
  распознавание обычных URL учитывать как соседнюю возможность, не заменяющую OSC 8.

Готовность исследования: точный gap по каждому backend/transport, контракт поведения
ссылки и план проверок end-to-end без изменения кода в текущем запросе.

### R3 Проверить наиболее полезные сценарии изолированно

Этот этап планируется для отдельного запроса на практическую проверку. Первые кандидаты:
native-dir-picker → project-launcher → workspace-sets/window-switcher → overlay-and-split
→ Claude/Codex resume → long-commands-status/flag-recent-agents.

Проверять два окна и два экземпляра, вызывающую split/hidden pane после swap,
смену foreground window во время picker, отмену без побочного действия, Unicode,
пути с пробелами/кавычками и текст prompt со спецсимволами. Для resume проверить
разные разговоры, cwd, профиль и параметры запуска после перезапуска.
Для событий — timeout/cancel/disconnect и restart identity.

Готовность: воспроизводимые шаги и фактический исход Windows/WSL отдельно. Отсутствующая
зависимость, неподдержанный режим и непройденная проверка имеют явный статус.
Использовать частные app-id/pipe и временные данные по правилам
[CONTRIBUTING](../../CONTRIBUTING.md); пользовательские sessions/config не затрагивать.
