# Repository preferences

- Create pull requests in the user's fork, `narma/agwinterm`.
- Target the `narma` branch by default, matching the fork's GitHub default branch.
- Merge pull requests using Squash unless the user explicitly requests another merge method.
- Do not introduce new runtime dependencies, such as Python or another separately installed interpreter, service, or runtime, on Windows, WSL, or remote hosts. Prefer existing bundled components, including the Rust Linux helper. Any exception requires explicit user approval before implementation; do not install dependencies implicitly. This restriction does not prohibit build/test-only tooling or libraries compiled into the shipped binaries.
- Local Windows UI tests default to dedicated Hyper-V VMs. Use the normal test entry point or `hyperv-ui.ps1 -Suite <suite>` / `-Test <test>` from an ordinary session: the installed UI host supplies the prepared image and handles privileged VM operations without per-run UAC. Do not request elevation for each test or bypass the installed worker. Its shared limit is two VMs / 8 GiB RAM. See `docs/hyperv-ui-tests.md` for one-time installation and maintenance. Explicit Sandbox use is available with `AGWINTERM_UI_BACKEND=Sandbox` or `sandbox-ui.ps1 -Background`. WSL tests automatically use the host distribution on a private non-input Win32 desktop via `wsl-ui.ps1`; this keeps their Windows UI off the user's desktop. Local entry points route before UI work. Never bypass routing with CI environment flags or fall back to the user's desktop. Host-free unit tests and fixture checks can run directly.
- If an automation tool's restricted environment denies Task Scheduler or named-pipe access, run the same worker-backed command outside that tool isolation as the same ordinary Windows user. Tool sandbox escalation is not Windows administrator elevation: do not use `Start-Process -Verb RunAs` for individual test runs.
